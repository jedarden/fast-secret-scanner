# Redacted Gitleaks findings review

The source research repository was scanned with installed Gitleaks 8.25.1,
the repository configuration extending Gitleaks defaults, and full redaction.
No matched value was printed or copied into this repository.

## Aggregate findings

| Rule | Findings |
|---|---:|
| `curl-auth-header` | 100 |
| `generic-api-key` | 52 |
| `curl-auth-user` | 3 |
| `private-key` | 2 |
| `stripe-access-token` | 2 |
| `kubernetes-secret-yaml` | 1 |
| **Total** | **160** |

There were 159 unique `(path, line, rule)` locations across 52 files. The full
Git-history scan and a current-tree scan produced the same rule counts, although
some paths differed because files moved.

| File type | Findings |
|---|---:|
| Markdown | 154 |
| YAML | 4 |
| Text | 2 |

The six non-Markdown locations were one generic API-key candidate in each of
two deployment manifests, one Kubernetes Secret candidate in another
deployment manifest, two generic API-key candidates in a credential-themed
text transcript, and one private-key candidate in a secret template. Source
repository names, paths, and line numbers are intentionally omitted from this
public report.

These are possible secrets, not confirmed live credentials. Documentation can
contain real copied values, and operational-looking YAML can contain inert
templates. Any candidate that could have worked must be revoked or rotated
before it is allowlisted.

## Influence on this scanner

The observed distribution motivated explicit rules for authorization headers,
curl username/password arguments, generic credential assignments, private-key
headers, Stripe prefixes, and added Kubernetes Secret blocks. The Rust scanner
also includes common provider prefixes with high security value and low
matching cost.

The earlier Perl prototype covered all 159 unique Gitleaks locations but added
35 candidates. That validated the two-tier idea: a conservative early tripwire
can catch the observed fat tail while Gitleaks retains comprehensive authority.

The Rust implementation was checked against the 52 current-tree files that
contained these findings. A location counted as covered when the corresponding
Rust rule family appeared within 20 lines; this accommodates Gitleaks matches
that begin at `curl` while the Rust scanner reports the header line.

| Gitleaks rule | Rust-covered unique locations | Unique locations |
|---|---:|---:|
| `curl-auth-header` | 100 | 100 |
| `curl-auth-user` | 3 | 3 |
| `generic-api-key` | 28 | 51 |
| `kubernetes-secret-yaml` | 1 | 1 |
| `private-key` | 2 | 2 |
| `stripe-access-token` | 2 | 2 |
| **Total** | **136** | **159** |

That is 85.5% coverage of the observed unique locations. The missing 23 are all
from Gitleaks' broad generic rule. This is consistent with the stated goal:
provider prefixes and the most common structural leaks are blocked quickly,
while Gitleaks retains the wider generic net.
